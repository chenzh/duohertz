# duohertz 纯视觉设计需求文档

> 版本：v1.1 · 2026-09-25  
> 用途：供品牌、UI、角色、动效设计及前端共同执行；正文控制在 4000 字以内。

## 1. 设计目标

duohertz（真我赫兹）是面向儿童、家庭、节奏游戏新手与轻度玩家的全年龄电子音乐节奏游戏。用户进入页面后数秒内应理解：这是明亮友好的电子音乐世界；一键可入门、双键可进阶、两人可同玩；每次敲击都会产生清楚的声音、波纹与光粒反馈。

核心视觉命题：**在深蓝电子空间里，用两束相互回应的频率，让玩家找到自己的节奏。**

## 2. 品牌规范

| 项目 | 内容 |
|---|---|
| 英文名 | `duohertz`，始终全小写 |
| 中文名 | 真我赫兹 |
| 中文 Slogan | 音你、真我赫兹 |
| 英文短句 | `Music for you. Be your true hertz.`，当前为待确认候选 |
| 玩法提示 | `Tap the beat. See the sound.`，不作为品牌 Slogan |
| 品牌性格 | 清澈、灵动、友好、未来感、共同参与 |
| 核心图形 | 双端点声波、双键互答线、同心频率环、折射几何、音符光粒 |

Logo 应表达“两个频率互相回应”，适用于小图标、分享卡及单色场景，避免直接使用通用音乐图标。

## 3. 视觉方向

整体像一个可进入、可触碰的“声音场”，而不是夜店、复杂控制台或赛博朋克战场。

- 深海军蓝／靛紫构成空间，冰白承载文字。
- 亮青表示第一键、可操作状态与声波；亮紫表示第二键、主操作与回应关系；粉紫只作少量舞台高光。
- 每屏仅保留一个视觉焦点，以色块、轮廓、留白和轻光晕分层。
- 角色轮廓、道具和动作方向须清楚；五类曲封可有不同母题，但共享蓝紫色域、标题安全区和品牌标记位置。

禁止使用旧品牌视觉与四轨暗示；不沿用珊瑚红／暖白漫画印刷主方向；不模仿第三方游戏，不用高密故障纹、持续闪烁、整屏粒子或幼儿化糖果风。

## 4. 设计系统

### 4.1 色彩

| Token | 色值 | 用途 |
|---|---:|---|
| Midnight | `#0B1232` | 全局背景 |
| Indigo Space | `#151A52` | 空间渐变 |
| Panel Blue | `#18244B` | 卡片、浮层 |
| Elevated Blue | `#273674` | 重点模块 |
| Ice White | `#F3F7FF` | 标题、正文 |
| Soft Text | `#D5E2F7` | 次级信息 |
| Frequency Cyan | `#69DFF5` | 第一键、聚焦、声波 |
| Reply Violet | `#9687F7` | 第二键、主按钮 |
| Success / Warning / Error | `#72E6B1` / `#FFDA75` / `#FF7E9A` | 状态反馈 |

蓝紫背景约占 70%，信息层约占 20%，亮青／亮紫强调不超过 10%。文字与关键控件达到 WCAG 2.2 AA。

### 4.2 字体与布局

- 品牌与页面标题：Sora Bold/ExtraBold；正文：IBM Plex Sans；BPM、键位、短状态：IBM Plex Mono。
- Hero 标题桌面 64–84 px、手机 42–56 px；手机正文不低于 16 px。
- 内容最大宽度 1140 px；桌面 12 栏、平板 8 栏、手机 4 栏；基础间距 4 px，常用 8/12/16/24/32/48/64。
- 大卡片圆角 16 px，小控件 8–10 px。玩法与系统面板可用硬边频率条；阴影只用于层级，不给全部组件加彩色发光。
- 所有操作目标至少 44×44 px，主按钮建议高 48 px；320 px 视口不得横向滚动。

## 5. 页面要求

### 全局外壳

桌面页头包含 Logo、Library、Characters、Radio；手机底栏包含 Home、Library、Play、Characters。当前项使用文字及轮廓或底线表示，底栏不得遮挡内容。

### 首页

结构固定为：分栏 Hero → 三首起步曲 → 电台入口 → 三名角色 → 更多曲目。Hero 左侧为标题、承诺和“一键开始”，右侧为可试的一／双键声波区。手机先显示主文案与开局操作；320×568 下主按钮完整位于底栏上方。

### 曲库

顶部放标题、搜索与五类曲风筛选；手机筛选单行横滑。默认展示 15 首，每次增加 15 首。曲卡包含封面、曲名、艺人、曲风、BPM、Play 与 Listen。桌面 3–4 列，手机优先单列。必须设计加载、空结果、失败和无更多内容状态。

### 角色

展示三名角色的正／侧面、Role、身份、性格、台词与故事。三人轮廓与能力形状不同，但材质和光影统一。手机一次突出一人，长故事按需展开。

### 电台

视觉比游戏页安静。当前曲目区突出封面、曲名、艺人、进度和播放控制；队列提供搜索与曲风筛选。筛选不得中断或隐藏当前播放状态；保留“用这首歌进入游戏”的清楚入口。

### 赛前

顺序固定为：曲名／封面 → 一键／双键选择 → 对应开局按钮 → Solo／Duo → 音量、键位、校准。一键为默认入口；高级设置默认收起。选中状态至少使用填充、描边、勾选或键数标识中的两种。

### 对局

视觉优先级：音符与判定线 ＞ 判定反馈 ＞ 分数／连击 ＞ 进度／暂停 ＞ 装饰。第一轨用亮青，第二轨用亮紫，并以位置和文字／符号辅助区分。Duo 展示两个独立一键区域与玩家标签，不默认营造胜负。Tap、Hold 头／身／尾和同时击打须轮廓不同；Perfect、Good、Miss 同时用文字、形状和位置反馈。粒子在 150–350 ms 内消失，不遮挡后续音符。

### 结算

优先显示曲名、完成状态、准确率和核心成绩。Duo 平行展示两名玩家，不默认宣布胜负。主操作为再次游玩或下一首；次级操作为选曲、电台和分享。提供 1200×630 横版与 1080×1350 竖版成绩卡模板。

## 6. 组件与动效

- Primary：亮紫或青紫渐变；Secondary：深蓝底加亮色描边；Tertiary：文字按钮；破坏性操作使用错误色。
- 按钮、输入、筛选和卡片必须交付 default、hover、focus、pressed、disabled、loading 状态。焦点环为 3 px 亮青、外偏移 3 px。
- 卡片 hover 仅做 2–4 px 位移、边框提亮或轻阴影；手机不依赖 hover 显示信息。
- 暂停、退出与断连使用居中模态层，背景降亮但保留歌曲上下文，主操作首先获得焦点。
- 按钮反馈 80–140 ms，卡片进入 180–260 ms，页面切换 220–320 ms，击打波纹 180–320 ms，结果揭示 400–700 ms。
- Reduce motion 下取消视差、粒子飞行和大幅移动，保留静态波纹轮廓、颜色变化与判定文字。禁止高频全屏闪烁。

## 7. 响应式与可访问性

必须交付 1440×900、1280×720、1024×768、844×390、667×375、390×844、320×568 画板。底栏不得遮挡操作；横屏优先保证音符、判定线、触控区与暂停可见，并处理 Safe Area、动态视口和 200% 字体缩放。

全部流程可用键盘操作；焦点顺序与视觉顺序一致；判定、错误、玩家和左右键均用文字／形状／位置辅助颜色；失败文案简短、友好、鼓励重试，不羞辱儿童和新手。

## 8. 交付物

- Figma Foundations：色彩、字体、间距、栅格、圆角、边框、阴影、图标、动效 Token。
- Components：导航、按钮、输入、筛选、曲卡、角色卡、播放器、模式选择、HUD、弹层及完整状态。
- Screens：首页、曲库、角色、电台、赛前、Solo、双键、Duo、暂停、结算、加载、空、失败、离线、权限拒绝、断连、旧链接过渡和 404。
- Prototype：首页到开局、曲库到电台、完整一局到结算三条流程。
- Assets：Logo SVG 多版本；32/180/192/512 px 图标；1200×630 OG；两种成绩卡；三人正／侧面透明立绘；1:1 曲封模板及裁切焦点。
- 标注必须使用 Token 名，并说明尺寸、状态、响应断点、键盘／触控、滚动及 Reduce motion 行为。

## 9. 验收清单

- [ ] 全路径只出现 duohertz 新品牌，视觉语言统一。
- [ ] 首屏无需长说明即可理解一键、双键和 Duo。
- [ ] 音符、Hold、判定与玩家区别不只依赖颜色。
- [ ] 三名角色与五类曲封既有差异，也属于同一世界。
- [ ] 320×568 无横向溢出或底栏遮挡；两档手机横屏关键操作可见。
- [ ] 触控目标 ≥44×44 px，文字与控件达到 WCAG 2.2 AA。
- [ ] 键盘、200% 字体和 Reduce motion 不丢失功能或反馈。
- [ ] 所有页面、组件状态、异常状态、资产与标注交付完整。

本文件只定义视觉目标，不代表品牌／角色清权、曲封签审、玩法手感、音乐质量或发布批准。

## 1. 用户命题 → 设计转译

| 原话 | 转译 |
|------|------|
| "玩的时候不是全屏的吗" | 霓虹层铺满 **viewport**，不局限于场地柱（现状：`.play-wrap` 居中柱 + 两侧纯黑） |
| "跟随连续得分" | 驱动值从 combo 换成 **ScoreStreak 连续得分**（见 §2） |
| "霓虹闪动，若隐若现" | 闪烁语法 = **低透明度 + 间歇 + 呼吸**，不是常亮更不是爆闪；霓虹灯管"接触不良"式的忽明忽暗 |
| "更炫酷一点"（上轮） | 密度随得分档位增长，但每一步都守 §7.6 平涂语言 |

## 2. 驱动重定义：ScoreStreak 连续得分

**规则**：
- **得分判定**（perfect / great / good，score > 0）→ streak +1
- **miss** → streak 清零（唯一清零途径）
- **冷却衰减**：超过 2s 没有得分判定，streak 每 0.5s −1（间奏不熄灯，但也不白亮）；下限 0

**为什么比 combo 合理**：combo 在 good 即断（PRD §4.4），标准难度 3 对象/秒下手感稍差就归零——灯光跟着 combo 走等于惩罚中游玩家。ScoreStreak 只认"你还在得分吗"，good 海玩家也能养出满级霓虹；miss 依然是明确的一刀。

**档位阈值**（首版，实施后调参）：

| 档 | ScoreStreak | 霓虹状态 |
|----|-------------|----------|
| N0 | < 30 | 无霓虹（默认墨场） |
| N1 | ≥ 30 | 场地两侧竖灯管若隐若现 |
| N2 | ≥ 70 | + 背景城市灯牌闪烁（play-bg 区域） |
| N3 | ≥ 120 | + 全屏呼吸边框 + 地面反射感 |

标准难度下普通玩家 ~15s 进 N1、~35s 进 N2——"够得着"是本次重设计的核心诉求。

**落点**：`src/engine/surge.ts` 内新增 `ScoreStreak`（与 `SurgeMeter` 同族纯逻辑 + 单测），`PlayField` 判定入口喂 `streak.apply(j)`。LIGHTING 灯光组的驱动值同步从 `combo` 换成 ScoreStreak（§2.2b 规格修订：灯具触发阈值按新标尺重标，跑马灯/光柱/扫光的语法不变）。

## 3. 全屏霓虹舞台（三层）

### L1 侧翼灯管（viewport 边缘）
- 场地柱两侧的黑色区域，各立 **2–3 根竖向霓虹灯管**（硬边圆角矩形描线，纯平涂，无辉光滤镜）
- 若隐若现：alpha 以 `steps()` 在 0 → 0.10–0.22 之间**非周期跳变**（模拟接触不良），呼吸周期 3–7s 随机相位，绝不同步
- 颜色：District 主色为基调，N2 起偶尔跳四道色（灯光师换色纸的延伸）

### L2 城市灯牌（play-bg 区域）
- `.play-bg`（封面图）之上叠 3–4 个小型"灯牌"色块（菱形/斜切矩形，§7.6 motif 语系），在视野边缘忽明忽暗
- N3 起灯牌随节拍眨眼（bar 对齐），但亮度封顶 0.18——氛围不抢判定

### L3 呼吸边框（全屏）
- 复用 ON AIR 错位边框的语法，铺满 viewport 四边；N3 时以 ~8s 周期极缓呼吸（alpha 0.04–0.14）
- ON AIR 档与之叠加：边框色随 District、跑马灯已在场——霓虹层只提供"底光"，不做第二份跑马灯

**若隐若现的硬语法**：任何霓虹元素的 alpha 上限 0.22；闪烁一律 `steps()` 跳变（平涂语言，拒绝 fade 渐变）；所有呼吸周期 ≥ 3s 且互不同相。

## 4. 技术方案（关键决策：CSS 承载，canvas 不动）

- **霓虹层 = DOM/CSS**：`.play-page` 下新增 `.neon-layer`（`position:fixed; inset:0; pointer-events:none; z-index` 介于 play-bg 与 play-wrap 之间）。灯管/灯牌/边框全是定位 div
- **闪烁/呼吸 = CSS `steps()` keyframes**，零 JS 逐帧成本；JS 只在 **ScoreStreak 档位切换时**写一次 `data-neon="0|1|2|3"`（沿用 `data-surge` 的零重渲染模式）
- **性能论证**：CSS 动画走合成器（opacity/transform），不进主线程；对比 canvas 方案（每帧多 N 次 fillRect）——全屏霓虹是常驻氛围，合成器承载是唯一不 吃帧预算的选择
- **降级**：`fancyFx` 关 / `prefers-reduced-motion` → 整层 `display:none`（霓虹本质是运动氛围，静态残影反而怪）；移动端小屏默认只开 L1（两侧空间窄，L2/L3 收益低）
- **与既有层叠序**：play-bg → **neon-layer** → play-wrap（场地柱） → canvas

## 5. PRD 合规与安全

- **§7.6 "不用渐变、柔光、霓虹辉光"的解读**：本方案中的"霓虹"是**霓虹灯管造型**（硬边描线 + 步进闪烁的表演效果），不是辉光滤镜/渐变发光。灯管本体平涂、闪烁是 alpha 阶梯——落在漫画符码的"城市夜景"语法内。**这是一个需要 PRD side-car 确认的解读**，若拍板"霓虹管可以"，在总纲 §7.6 补一行 as-built 注记
- **闪烁安全（WCAG 2.3.1）**：任何区域闪烁频率 ≤ 1Hz（远低于 3 flashing/s 红线）；全屏呼吸 ≥ 8s 周期；`prefers-reduced-motion` 全关
- **判定优先级（§7.3）**：霓虹层 z 序在场地之下、alpha 封顶——永不与音符/判定线争夺对比度

## 7. 开放决策点

1. **PRD §7.6 解读**：霓虹灯管（硬边+步进闪烁）是否放行？——本方案的地基，先拍这个
2. **ScoreStreak 是否进结算**：N3 峰值是否在 Results/海报留痕（与 PEAK SIGNAL 并列还是合并表述）？
3. **阈值口味**：30/70/120 是"普通玩家 35 秒满级"的首版，偏松偏紧等试玩反馈
4. **移动端**：小屏只开 L1 是否正确，还是干脆全关

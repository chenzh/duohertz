### AudioBar 播放条四项优化（用户指定：视觉/交互 + 健壮性 + 键盘无障碍 + 拖拽性能，全选）

改动文件：`apps/beatscape/src/components/AudioBar.tsx`（重写）、`apps/beatscape/src/styles.css`（+52 行）。

**① 拖拽性能（原最大问题）**
- `getBoundingClientRect()` 从每次 `pointermove` 调用 → 改为 `pointerdown` 时缓存进 `rectRef`（与审计 P2-7 同一思路）。
- 新增 `paint(seconds, total)`：拖拽期间**直接写 DOM**（fill 宽 / thumb 左 / 时间文本 / 气泡文本与位置），不再 `setTime`。
- `setTime` 只在 `pointerup`（`endDrag`）提交一次 → 每次手势最多 2 次 re-render，而非"每帧一次 re-render"。
- 拖拽期间 `onTimeUpdate` / `onProgress` 早退，消除进度条被原生事件回写造成的抖动。
- 补 `onLostPointerCapture` → 兜底结束拖拽（指针被系统抢走时不卡在 dragging 态）。

**② 键盘 + 无障碍**
- `role="slider"` 补 `tabIndex={0}` + `onKeyDown`：←/↓ −5s、→/↑ +5s、PageUp/PageDown ±10s、Home/End、Space/Enter 播放暂停，全部 `preventDefault`（阻止页面滚动）。
- 补 `aria-valuetext`（`M:SS of M:SS`，此前读屏会念裸秒数）；`aria-label` 带上 `label`（如 "Seek — Preview xxx"）。
- CSS 补 `.audiobar-track:focus-visible` 橙色焦点环。

**③ 健壮性**
- 补 `onEnded`：按钮不再永久卡在 pause 图标，并把 `currentTime` 归零便于重播。
- 补 `onError`（复位 playing/ready）、`onDurationChange`（`preload="none"` 场景 duration 迟到的兜底）。
- `el.currentTime` 赋值前检查 `readyState > 0` —— Safari 在元数据未加载时会抛 `InvalidStateError`。
- `src` 变化时一并重置 `buf` / `rectRef` / `dragRef`。
- `fmt` 从组件内提升到模块作用域（不再每次 render 重建函数）。

**④ 视觉 / 交互**
- 新增缓冲进度 `onProgress` → `bufferedEnd(el)`（取包含播放头的那段 buffered range）→ `.audiobar-buffer`。
- 新增时间气泡 `.audiobar-bubble`：拖拽 / 悬停 / 聚焦时显示，内容随拖拽实时更新。
- thumb 悬停 `scale(1.25)` + 90ms 过渡。
- `.audiobar-track::after` 上下各撑 7px，把 8px 的点击热区扩到 ~22px（触屏可用性）。
- 注意：`.trend-card` 有 `overflow: hidden`，但 AudioBar 是其**兄弟节点**（在 `.trend-card-wrap` 内），气泡不会被裁切。

**React 细节坑（已规避）**
`paint()` 用 `textContent` 改写时间文本。按 DOM 规范 `string replace all`，只有当该 span 恰好有**唯一一个 Text 子节点**时才会复用原节点；若写成 `{a} / {b}`（3 个文本节点），`textContent=` 会移除并新建，React 持有的 text node 脱钩 → 拖拽后时间显示静默冻死。故时间 span 写成单一插值 `{`${fmt(time)} / ${fmt(dur)}`}`，气泡 span 同理单行写法。

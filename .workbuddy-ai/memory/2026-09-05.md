- **谱面跟拍感修复（已提交 `e265521`，已 push origin/main）**：BeatScape 105 首 × 3 档共 315 张谱面全量重生成。
  - 根因：`scripts/beatscape-chartgen.py` 的 `select_onsets()` 排序键是**纯能量** `key=lambda x:-x[2]`，onset 检测密度 ~11/s 远超拍密度（90 BPM 八分仅 3/s），"最响 onset"大量落在拍间微位置 → 每音有声但间隔忽长忽短 → "不跟拍"。
  - 修法：排序键 = 能量归一化 + `grid_w × grid_affinity`（正拍1.0 / 八分0.78 / 十六分0.5 / 格间0）。grid_w 经扫描定为 **easy 0.6 / standard 0.5 / hard 0.4**（约束：选中 onset 平均响度 ≥ 全曲均值，w 再大就会挑到贴格但听不见的点，响度x < 0.95 出现踩空感）。`enforce_peak_nps` 在 beat>0 时优先删**最不贴拍**的音符以保骨架。
  - 新增 `beatscape-chart-gridfit.py`：用**最优相位搜索**（差分数组投票，O(n)）衡量"音符是否构成规整脉冲网格"，并加 `--loud`（读音频算响度x）、`--catalog-dir`、`--fail-under`（CI 门禁）、`--worst`。
  - 验证（修正后的最优相位指标，见下条教训）：网格内% 中位 easy 46.7→81.7 / std 32.6→77.1 / hard 33.9→58.0；音符数最多 -4.7%；仅 3/3/4 首退化。tsc 0 / vitest 122。

- **关键教训：诊断指标本身也会骗人（务必先验证尺子）**。最早用 `beat_map.first_beat_ms` 当相位基准量网格内%，得到 easy 中位 31%（以为很糟）。后来发现 `first_beat_ms` **运行时根本不读**（PlayField 只读顶层 `audio_offset_ms` 且生成器恒为 0），它只是元数据，检测还常偏（bs-s5-01 偏 2 秒 → 原相位 21.7% vs 最优相位 84%）。拿歪尺子量会系统性误判。正确做法是 gridfit 对 offset 做最优相位搜索，衡量"音符是否构成规整脉冲网格"（= 玩家真实感知），而非对齐某个绝对时钟。改完尺子重测才得到真实基线 46.7%。

**关键解耦事实**

- `GameSession` 不触碰 DOM/Audio，由外部时钟（Conductor）驱动；判定内核可单测（playState.test.ts 8 例）。
- `Conductor.songTimeMs()` 是**唯一歌曲时间真值**：首次 3s countdown 属同一时间轴；暂停冻结，Resume 的 3s 再入场由同一 AudioContext deadline 排程并保持歌曲时间不动，变速按 rate 累积，杜绝 UI 定时器与音频漂移。
- 渲染循环直接读 `sessionRef.current`，每帧零 React setState；街区角色先画入 Canvas 环境背景，轨道、判定线、音符、瞬时判定、中央连击与键帽随后绘制，确保玩法反馈永远压住立绘。`PlayHud` 以独立 20Hz rAF 从 `LiveStats` ref 直写 Score / live Accuracy / chart Progress / SIGNAL，以及仅 Arcade 可见的 HP 标签、余量与精确值，仍不触发 React 重渲；零判定时 Accuracy 显示中性 `—`，首次判定后才显示实际百分比。四档累计判定只在 Results 可见，运行中隐藏的状态镜像仅供暂停与输入诊断。

## 3. 玩法形态

**4 道下落式（Neon Lanes）**，lane 0–3 左→右，与总纲 §4.1 一致。四种音符类型全部实现：

| 类型 | 视觉 | 输入 | 判定 |
|------|------|------|------|
| Tap | 霓虹菱形（黑描边 + 高光，唯一造型） | 按下 | 单次四档 |
| Hold | 独立头菱形 + 半透明身条 + 0.95× 独立尾菱形；按住时身条描边、尾标提升 | 头按下持续至尾释放 | 头四档 + 尾四档（=2 判定对象） |
| Chord | 同帧多道菱形 + 黑框/米白内芯连接轨；部分命中时保留组关系 | 每键独立 | 每键独立判定（漏道 Miss） |
| Slide | 头菱形 + 目标道轨迹 + 0.95× 尾菱形；起点激活后高亮虚线，目标提前持有时变 5px 实线并放大尾标 | 起点窗按 `lane` 激活，再按/滑入相邻 `to`；可在完成窗到达，或提前到达并持续按住至 `end` | 起点不计分；完成时按首尾较差档位结算一次，尾窗三档 +20ms |

## 4. 核心判定与计分真值（代码级）

### 4.1 判定窗（`engine/judge.ts`，PRD 总纲 §4.3 ✓ 一致）

| 档位 | Arcade / Practice | Casual | 分 | 连击 |
|------|------|------|----|------|
| Perfect | ±15 ms | ±28 ms | 300 | 不断 |
| Great | ±30 ms | ±55 ms | 200 | 不断 |
| Good | ±50 ms | ±90 ms | 100 | **断** |
| Miss | 超 Good | 超 Good | 0 | 断 |

- **Hold 尾部**：`judgeHoldTail` 对三档**全部 +20 ms** 吸附（15+20/30+20/50+20）——比总纲「Good 窗 +20」略宽，属更宽松的 as-built 解释。成功松开保留原判定音并叠加短促下行的程序合成释放音；Miss 不叠加，关闭 Hitsounds 时静默。该提示不增加判定对象，也不改变尾窗或 HP。
- **空按**：`press()` 找不到候选 → 返回 null，无惩罚、只响 `playKeyTick`（PRD §4.14 ✓）。
- **幽灵击**：Miss 后 note 已 `done`，同道再按不匹配任何对象 → 忽略（✓）。
- **防重复 / 所有权**：键盘 `e.repeat` 忽略；`LaneInputTracker` 统一键码、pointer 与每个 gamepad button source，同道 20ms 防抖。一个 lane 仅在第一个 source 到达时 press、最后一个 source 离开时 release，键盘、触控、手柄或同道多源不会提前截断 Hold（`LANE_DEBOUNCE_MS=20`，PRD §4.14 ✓）。
- **谱面输入公平闸门**：release 要求任意同 lane press 对象间隔 ≥100ms，并禁止 Hold 占道期间再放同 lane press；自动生成器会在 250–550ms Slide 时长内就近避开冲突尾点。现库 315 张谱均能经真实 `LaneInputTracker` 所有权/防抖链完成 AP 模拟。
- **自动 Miss**：`tick()` 对超 Good 窗仍未击中的对象逐个补 Miss；Hold 头 Miss 时**头尾双 Miss 入账**（2 个判定对象都算 Miss）。
- **Slide 单对象**：起点命中只保存候选档位并激活轨迹；目标道在尾窗内到达/释放时即时判定，提前到达并持续拥有该道则在歌曲时间到达 `end` 时按尾点 Perfect 完成。提前离开且尚未进入尾窗会放弃持有，后续超时整条只登记 1 Miss；完成仍取首尾较差档位并只登记一次。目标道窗口与 `judgeHoldTail` 一致，三档均 +20ms。
- **Slide 失败纠错**：起点已命中但从未到达目标道的超时 Miss 显示 `REACH TARGET`；曾提前到达目标道、随后在尾点前离开的超时 Miss 显示 `HOLD TO END`；整条未起步没有可归因的后续动作，仍只显示 `MISS`。仅保存“目标曾到达”这一呈现事实，不改变单对象计分、窗口、HP 或音效。
- **Slide 锁定与完成反馈**：轨迹未激活时为弱虚线，起点命中后提升为 3px 高亮虚线；提前进入目标道且真实输入仍拥有该道时改为 5px 实线，并以 1.2× 外层 + 1.06× 主尾标确认已锁定。触屏布局在首次锁定及中断后合法重抓时给 6ms 轻触觉；已分配标准手柄使用 22ms 轻高频 `dual-rumble`。两者服从同一 Haptics 开关且独立于 Hitsounds；能力缺失或 API 拒绝时静默。成功完成时在原判定音上叠加短促上扬的程序合成锁定音，Miss 不叠加，关闭 Hitsounds 时静默。释放、暂停清理或完成会同步撤销视觉状态，反馈不改变判定与得分。

### 4.2 计分 / 准确率 / 评级（✓ 与总纲 §4.4 完全一致）

```text
单次得分 = 基础分 × 连击倍率（0–49 ×1 · 50–99 ×2 · 100–199 ×3 · 200+ ×4 封顶）
MaxScore = TotalNotes × 300 × 4      // Local Board 拒收 score > MaxScore×1.01
Accuracy = (P×1.0 + Gr×0.75 + Go×0.40) / TotalNotes × 100   // 2 位小数
Grade：S ≥95 · A ≥90 · B ≥80 · C ≥70 · D <70
FC = 判定合计===totalNotes 且 good===0 且 miss===0（Great 可叠）
AP = 判定合计===totalNotes 且 perfect===totalNotes
TotalNotes：tap/slide=1 · hold=2（头尾） · chord=n 键
```

Perfect / Great 推进连击后取倍率；Good 断连但仍按重置后的 ×1 计入 100 基础分，Miss 才是 0 分。Chord 各 lane 只按自身相对 `note.t` 的窗口独立判定，无额外 15ms 键间截止线；每道仍即时产生独立星爆与真实得分浮字，但主判定词等整组完成后只显示一条最差档位摘要。同档位取绝对时差最大者决定 EARLY/LATE，摘要居中于整个和弦跨度。
正常键盘/触控命中的非 Miss 判定会在判定线附近显示与当次真实增量一致的分数浮字：Perfect / Great 使用已经提交的 Combo 倍率，Good 显示 `+100`；Miss 不显示得分。自动 Chord assist 走同一反馈规则。
已有 Combo 被 Good 或 Miss 归零时，场中央显示 520ms `COMBO BREAK`，并保留既有红色暗角与专用断连音；同帧清除未结束的 Combo 里程碑，避免断连后继续庆祝。状态机以 `comboBreaks` 单调事件序号记录断连，Canvas 不从帧末 Combo 反推，因此同帧后续命中已把 Combo 恢复到正数时仍不会漏报。文字只做原位淡出，Reduce Motion 下仍保留。
Combo 里程碑 [10,25,50,100,150,200,300] 按上一帧 Combo 到当前帧 Combo 的前开后闭区间触发，不要求帧末值恰好等于阈值；同帧 Chord 从 9 推进到 11 时显示 `10 COMBO!`。单帧跨过多个阈值时取最高值；同帧若发生断连则由 `COMBO BREAK` 优先，不同时庆祝。
Hold 尾判 FX 保留 release 来源：主动提前松开显示 `EARLY RELEASE`，主动延后松开或持续按过尾点显示 `LATE RELEASE`；成功但偏差 ≥8ms 的尾判也使用 release 文案。整条 Hold 未起按没有 release 来源，仍只显示 `MISS`。320px 第一/第四道先把主判定文字组按真实字体宽度、描边、动画缩放和震屏位移约束进 Canvas，再单独约束长副标签；星爆和得分浮字保持真实道位。Chord 不逐道重复主词，而是在整组完成后绘制一条组级摘要，避免相邻 lane 在窄屏形成文字墙。
Slide 超时 FX 保留目标交互历史：从未到达目标道显示 `REACH TARGET`，到达后提前离开显示 `HOLD TO END`，整条未起步不伪造手势原因。长文案与 Hold release 共用窄屏边界约束。

### 4.3 HP（Arcade 专属，✓ 总纲 §4.5）

初始 100、封顶 100；Perfect +2 · Great +1 · Good 0 · Miss −7 · **Hold 尾 Miss −5**（主动超窗释放与自动尾超时共用；整条未起按为头 −7 + 尾 −5，共 −12）。左上 HP 条在真实下降时短暂显示精确 `−N`；HUD 同次采样捕获多个扣血对象时显示真实聚合差值，初始采样与回升不显示。HP≤0 → `failed`，触发失败的判定正常入账后立即停止当前 `tick()` 批次、音乐与后续判定并冻结输入，不得继续登记同帧剩余过窗对象；场内显示 300ms `SIGNAL LOST / HP DEPLETED` 后结算且不上榜。Duo 已失败半场持续保留失败卡，另一半场可继续；结算时通关方无条件胜过失败方，双方状态相同才比较 score，同分为 `DEAD HEAT`。Casual/Practice 无 HP、失败或扣血徽标。

### 4.4 三模式（✓ 总纲 §4.5 + 一个新增特性）

| 模式 | 失败 | 变速 | 特性 |
|------|------|------|------|
| Casual | 无 | Note speed 0.5–2.0×，只改可见下落时长（音频与判定窗不变） | 判定窗放宽 28/55/90 |
| Arcade | HP 归零 | Note speed 0.5–2.0×，只改可见下落时长 | 上 Local Board |
| Practice | 无 | Note speed 0.5–2.0×；准备卡与暂停层另选本局 0.5× / 0.75× / 1× 音画同步 tempo；基础 tempo 高于 0.5× 且连续 **3 Miss → `setRate(0.5, 5000)`** 临时减速 5s（`consumeSlowTrigger`），场内显示倒计时并恢复所选 tempo | 判定窗仍用 Arcade 毫秒值 |

PB 只由成功完成的整曲 Arcade 写入；Casual / Practice 可进入完整局 run history，但不产生 PB 或 Local Board 纪录。score 相同时以更高 Accuracy 更新 PB。

排名写入还要求四档 judgment 合计精确等于 `TotalNotes`，并检查 Accuracy、MaxCombo 与 MaxScore 边界。当前写入 `scoringVersion=2`；读取时仅淘汰 10 张受旧版 Slide 首尾双计分影响的 Standard/Hard 旧纪录，所有未受影响曲目与 Easy 历史成绩继续保留。

**Note speed（统一玩家语义）**：Settings 滑杆为 0.5–2.0×，Track 开玩区与普通完整 Play 准备卡另有 ±0.25× 快调并立即保存。准备卡按钮均 ≥44px，Start 后从 ready card 消失；运行中的视觉速度保持稳定，玩家可 Pause 后在 Quick controls 以 0.05× 精调，冻结状态立即更新当前单场或两块 Duo 的可见 approach，Resume 仍先走 3 秒倒计时。调整不重建 session、renderer、音乐时钟或已解码音频。准备卡保存失败时当前 run 仍生效并显示 `This run only`；暂停保存失败则保留旧值并报错。未完成的 First Shift 首关与 Home demo 保持静态读数。引擎历史字段 `scrollBias` 存的是可见时长倍率的倒数，所有换算统一走 `lib/noteSpeed.ts`。旧 `casualSpeed` 双倍率已废弃并在读取时忽略，避免 UI 的 0.75× 实际产生约 1.33× 的反向手感。

**Practice tempo（本局训练速度）**：只在单人 Practice 准备卡与暂停层提供同一组 50% / 75% / 100% 原生 radio。玩家可在第一拍前选择，首个音乐源直接使用所选倍率；局中选择同时改变音乐与谱面时钟，并贯穿 Resume、Restart track/section 与当前 run 的自动 Drill 轮次。新 run 重置 1×，不写 Settings；恢复/轮间倒计时始终是 3 个真实秒。手动非 1× 时 HUD 持续显示 `Practice tempo`；自动 0.5× assist 显示剩余秒数并在结束后恢复所选档位，手动 0.5× 不伪装成 assist。320×568 准备卡首屏同时容纳 Start、四轨提示、击打时机、Note speed 与三档 tempo，不横向溢出。Casual、Arcade、Duo、Daily 与挑战路径不暴露该控件。

**Background dim 与暂停安全/辅助设置（玩法可读性）**：Settings 与暂停 Quick controls 共用 0–100% Background dim，默认 25%；暂停 Quick controls 同时提供 0.5–2.0× Note speed、Hitsounds、Haptics、Reduce motion，并在具备触摸能力的设备显示 Thumb chord assist。暗层在环境 wash、光束和角色立绘之后绘制，轨道、判定线、音符、判定反馈与 HUD 随后覆盖，因此最大暗化仍保留完整玩法信息。暂停中成功保存后通过 settings 广播即时更新单人或两块 Duo：Background dim 更新环境层，Note speed 更新可见 approach，Reduce motion 与 Haptics 更新当前反馈，Thumb chord assist 只影响尚未完成的判定；这些变化都不重建 rAF renderer、session、音频或计分，也不回写既有成绩。Note speed 与 Chord assist 仅在 ready / paused 状态同步，运行中的跨标签页变化延迟到下一次暂停，恢复仍走 3 秒安全倒计时；Fancy FX 与 timing offset 继续锁定在开局值。

**Settings switch 控件**：Hitsound、Haptics、Fancy FX、Reduce motion 与触屏 Thumb chord assist 继续使用原生 `checkbox`，读屏和表单状态读取 checked 真值；视觉统一为硬边 switch，并始终显示 `On / Off`。透明原生 input 覆盖 48×44px 操作区，整行 label 仍可点；键盘 Space 原生切换，`:focus-visible` 在 switch 外显示独立高对比环。手机与桌面共用同一 DOM 和状态合同，不得只靠颜色表达开关值。

**Settings range 控件**：Music/SFX volume、Playfield background 与 Note speed 继续使用原生 `range`，因此读屏值、键盘 Arrow 与既有手柄 UI 导航都沿用浏览器真值。输入盒高度统一为 44px；内部 8px 硬边轨道以 CSS 变量实时绘制已选进度，24px 方形滑块提供明确抓取点并在 `:focus-visible` 时显示高对比环。样式层不得改变字段现有 min/max/step 或自动保存。

**Settings 时序微调控件**：Board name 与 Global offset 输入区均至少 44px。Global offset 使用文本草稿承载 `-` 等未完成输入，但以 `role=spinbutton` 暴露 −200..+200 数值语义；合法整数即时保存，空值、孤立负号、越界及非有限值显示错误且不得覆盖最后一次合法存档。Arrow 调 1ms，PageUp/PageDown 与三个触控按钮调 10ms / 归零；按钮均至少 44px。该手动微调不改变 Calibration 的测量与返回路径。

**★ Chord Assist（总纲未记载的 as-built 特性）**：任意具备触摸输入的设备都能在 Settings 看到并关闭该开关；手机布局默认开启，但辅助资格按每次命中的真实输入来源记录，而不是按整台设备判断。同手和弦（lane 0+1 或 2+3 叠在一只拇指上）超时未按的那条道，只有同手搭档道由 `pointerType="touch"` 命中时才 **记 Great 而非 Miss**（故意不记 Perfect，保 AP 公平）。补判 FX 标记 `chord-assist`；整组完成后主 `GREAT` 居中于和弦跨度，`ASSIST` 副标签仍保持在真实补判道中心，提交补判的超时帧不得生成虚假的 `LATE`。Surface / 平板上的外接键盘、鼠标与手写笔不会获得补判；其精细主指针仍保留桌面布局和默认展开的 Keyboard controls。跨手和弦（1+2 / 0+3）不受影响。这是移动端双拇指握法的核心公平性设计（`PlayField` 输入来源 → `playState.sameHandPartnerStruck`）。

### 4.5 下落几何（`engine/geometry.ts` — ⚠ 与总纲 §4.10 有偏差）

```text
as-built:  approach_sec = (64 / AR) × (60 / BPM) × (1 + scrollBias)
总纲 §4.10: approach_beats = 50 / AR
```

- 常量 `APPROACH_VISIBLE_BEATS = 64`（比总纲的 50 **多 28% 可见时间**，下落更慢、更易读）。
- 拍速感保留：160 BPM 显著快于 88 BPM（时间基随 BPM 缩放）。
- 判定线 = 短边 × **15%** 距底（`RECEPTOR_RATIO=0.15`，减 safe-area，✓ 总纲 §4.12）。
- **视觉缓动**：进度 >88% 后做 cubic ease-in（仅影响下落观感，不影响判定时刻——注释明示 "timing unchanged, only scroll feel"）。
- 进场放大：音符接近判定线 64px 带内放大 1.22×（`NOTE_PROXIMITY_GROWTH=0.22`）并提亮。

> 处置建议：**以 as-built 64 为手感真值**，反向修订总纲 §4.10（或在总纲登记变更单），避免后续 AI 按 50 复原。

### 4.6 对局状态机（as-built）

```text
Loading(decode m4a) → needsStart(Tap to enter the Scape / hero autoStart；可选 Sound check 有 busy / success / retry 状态；Home Play+Sound 启动失败保留 demo 原地重试)
  → begin(): 3s Countdown（时间轴负段，A5→C♯6→F6 递升节拍器，主曲未起不判定）
  → Playing（唯一时钟 = AudioContext；浏览器支持时持有一把 screen Wake Lock）
      ⇄ Pause（手动按钮；visibility hidden / window blur / AudioContext non-running → 自动 Pause；
               Resume / Keep playing 先由用户手势恢复 AudioContext，成功后才 3s 同轴再入场；

               单人 Restart 先解锁音频，成功后才清旧局；失败保留旧暂停局并允许重试；

      → Exit：`ExitGameDialog`（冻结音画；Keep playing / Esc 经 3s 再入场，Leave 离开）
  → Finished（任一）：
      ① Arcade HP=0（立即停谱/冻结输入，失败卡保持 300ms，不写榜）
      ② 全部对象结算 && 歌曲时间 ≥ 末音 end + 500ms

  → full variant：writeLastRun(bs_last_run, session + local) → nav /results

```

## 5. 输入系统

键盘与 pointer 判定使用浏览器收到物理输入时记录的 `Event.timeStamp`，Gamepad press/release 边沿使用 W3C `Gamepad.timestamp` 提供的最新硬件数据更新时间，而不是只看 React handler 或下一次 rAF 实际获准执行的时刻。时间戳先兼容归一 modern monotonic / legacy epoch 两种格式，再把当前权威 WebAudio 歌曲时钟按“输入年龄 × 当前播放倍率”回投；因此主线程短暂繁忙不会把准点 Tap、Hold 头尾、pointer 滑道或标准手柄输入误判成 Late。补偿上限为 250ms，NaN、0、过旧、未来或无法对齐的值全部回退到当前 handler / polling 时刻；DOM 输入防抖也使用同一物理事件时间轴。Gamepad sampler 由唯一 Canvas renderer 在每帧 `session.tick()` 之前调用，确保合法输入边沿先于该帧自动 Miss；不再维护第二个独立 rAF。

### 5.1 键盘（`input/keyMap.ts` — ⚠ 默认键位与总纲不同）

- **绑定的是物理键码 `KeyboardEvent.code`** 而非字符：法/德键盘布局下四道仍在同一物理位置，且可绑定方向键；旧版单字符存档经 `normalizeKeys` 自动升级，`key` 作为兜底匹配。
- **键帽按当前实体布局显示**：`useKeyLabels` 在支持的浏览器通过 [WICG Keyboard Map](https://wicg.github.io/keyboard-map/) 把物理 code 映射为当前键盘印字，并监听 `layoutchange`；AZERTY 的 `KeyA / KeyS / KeyW / KeyD` 因而显示 `Q / S / Z / D`。API 缺失、拒绝或返回空值、Dead key、控制字符/异常长标签时默认回退既有 `keyLabel`。玩家可在 Settings 的 Printed key labels 手动选 US QWERTY / French AZERTY / German QWERTZ；手动映射覆盖常见字母换位，适用于不提供布局 API 的浏览器。该选择仅改变 Settings、Home、Play、Duo、Calibration 的可见/可访问标签，不改 `bs_keys`、输入所有权或命中判定。
- **默认 = Arrow keys（← ↓ ↑ →）**——注释明示 "the Friday Night Funkin' layout"；总纲 §4.1 写的 D F J K 现为三预设之一：

| 预设 | 键码 | 定位 |
|------|------|------|
| `arrows`（默认） | ← ↓ ↑ → | FNF 布局 · 新手 |
| `wasd` | A S W D | 游戏手位 |
| `dfjk` | D F J K | osu!mania 老玩家 |

- Settings 逐道监听重绑（Esc 取消；Ctrl/Cmd/Alt 组合交还浏览器并继续等待；Tab 退出等待并原生移焦；Shift 加普通键按物理位置绑定；两道同键禁止保存）。Arrow keys / WASD / D F J K 以互斥 `radiogroup` / `radio` 暴露当前布局：唯一 Tab 停靠点，方向键循环，Home / End 跳到首尾；自定义逐道绑定时首个预设仍可达。逐道按钮读出当前键与等待按键状态；重复键在绑定组声明 invalid 并关联 alert。
- 键帽提示绘制在判定线下方（桌面或已识别外接键盘的触屏设备），按道着色、按下反色。赛前和 3 秒倒计时始终显示；`loadRuns()` 中不足 3 个有效完整局时整局常驻。第 4 局起单人 Casual / Arcade 在 GO 后 650ms 淡出，Resume / Restart 倒计时重新显示并再次淡出；Reduce Motion 在 GO 后直接隐藏。Practice、Duo（两套键位需持续辨识）与 Home hero 常驻；纯触屏不分配键帽精灵。Home 与赛前准备卡把键帽组作为带 `Lane keys: …` 名称的可访问图示；视觉短句只说明 `Hit the line`，不在键帽下重复完整键位。
- **Duo 座位分流**：桌面键盘按物理左侧键区 / 右侧方向键区决定双场顺序，避免两位玩家交叉手；粗指针触屏不读取键盘布局决定座位，固定 P1→P2。ready 与 live meta 改为每人 `Tap 4 lanes`；竖屏按实际上下场显示 Top/Bottom，≤520px 高短横屏与宽屏显示 Left/Right。结果列复用同一可见场地顺序。
- 全局对局监听只接管无 Ctrl / Meta / Alt 的玩法键；浏览器的 Ctrl/Cmd+R、Ctrl/Cmd+P、Alt+方向键及其他系统组合保持默认行为，不得误触 lane、R 重开或 P 暂停。Shift 单独仍可与绑定键/R/P 共用；`keyup` 始终清理已有 source，避免玩家按住 lane 后再加修饰键造成卡键。
- 准备层期间全局对局监听不接管任何玩法键；即使 Space / Enter 已绑定为 lane，聚焦的单人或 Duo 原生 Start 按钮仍可由该键激活。开局事务成功并建立倒计时后，同一物理键才进入 lane 所有权。

### 5.2 标准手柄（`input/gamepadInput.ts`、`input/useGamepadAssignments.ts`）

- 只接入浏览器声明 `mapping="standard"` 的控制器，不猜测 raw / vendor-specific 布局；映射遵循 [W3C Gamepad 标准布局](https://www.w3.org/TR/gamepad/)：D-pad 左/下/上/右（buttons 14/13/12/15）与右侧 face diamond 左/下/上/右（buttons 2/0/3/1）都对应 lane 0–3。`pressed` 或模拟值 ≥0.5 视为按下。
- 对局中按控制器 index 由唯一 Canvas 游戏帧读取一次最新 `navigator.getGamepads()` 快照，并严格先于同帧 `session.tick()`；新发现的 press/release 边沿以该快照的 `Gamepad.timestamp` 回投判定时刻，避免 rAF 相位、自动 Miss 顺序或短暂主线程繁忙把准点输入降档。时间戳不可信时直接使用当前轮询时刻。API 缺失、权限受限、非标准控制器或断连时静默保留键盘/触屏，不阻断开局。
- 单人分配第一只可见标准手柄；Duo 使用稳定座位，幸存 P2 不会因 P1 断连被提升成 P1，新控制器只补空座。两个场地只轮询各自 index，P2 输入不得串入 P1 计分。
- 已分配手柄在开局后消失或切换 index 时，字段先释放该手柄拥有的全部 lane，再自动冻结；Duo 通过父级 debounce 只冻结一次。暂停层显示 `Controller disconnected` / `reconnected` / replacement 状态并说明键盘与触屏仍可用；恢复仍走显式 Resume/Menu 与 3 秒安全倒计时。赛前变化只刷新 ready card，不留下过期警告。

### 5.3 触控

- `pointerdown/move/up/cancel/lostpointercapture` + `setPointerCapture`；每个 pointer 是独立 source，move 滑入新道 = 释放旧道 + 按下新道（天然支持滑键手势）。同道多指只在最后一指离开时抬道；键盘和 pointer 也共享这一所有权。
- **触控轨道所有权与 5% 边缘 guard**：以可见 Canvas 的 DOMRect 将视口 `clientX` 映射到四轨，左右各 5% 区域拒绝新的初始触摸；已合法拥有外轨的 captured pointer 短暂漂入 guard 时保持原 lane。触控拖动须越过当前轨边界 8px（极窄轨取轨宽的 15%）才换轨，避免几像素的拇指抖动截断 Hold；首次触摸、鼠标/手写笔拖动不施加该缓冲，明确滑到目标轨深处仍可完成 Slide。`pointerup/cancel/lostpointercapture`、Pause、系统/方向中断、重开、换谱与卸载均释放或清空 source，防止卡住 Hold。
- **浏览器手势隔离**：只有实时 `.play-canvas` 使用 `touch-action: none` 与 WebKit touch-callout 抑制；Canvas `contextmenu` 被取消，且 `button !== 0` 的右键/手写笔侧键在进入 lane ownership 前直接拒绝。沉浸式 `html/body` 使用 `overscroll-behavior: none` 阻断滚动链与边缘回弹，离开 Play / Duo 时清理；准备、暂停和错误 overlay 不继承 Canvas 手势锁，继续允许纵向触控滚动和页面缩放。Library 等普通路由保持浏览器默认行为。
- 判定线几何、热区=道宽；对局自动进入 immersive 模式（body class 隐藏站点 chrome）。单人和 Duo 的开始手势会在首次 `await` 前同时发起音频解锁与全屏请求，标准 / WebKit API 共用一条能力层；触屏页保留手动 Fullscreen 兜底，进入后同一控件切换为具名 `Exit fullscreen` 的向内收拢图标，激活后复用 `fullscreenchange` 安全路径退出并自动暂停，退出完成后恢复 Fullscreen fallback；不支持 API 时不渲染死按钮。≤520px 的单人/Duo 顶栏把该控件收为保留精确可访问名称的 44×44px 四角图标，为曲名与当前模式释放空间；单人 Play 再把完整身份映射成 `tier · mode/Daily/Goal/section/Rep N/M` 紧凑视觉状态，Duo 显示 `tier · mode`，两者的完整字符串均以视觉隐藏文本与 `title` 保留，不能让重复身份把曲名压成省略号。更宽触屏保留文字标签和完整身份。已开始且正在运行的对局若由应用内控件、系统或浏览器退出全屏，会自动暂停，避免退出动画期间产生免费 Miss；玩家主动 Resume 后再入场。
- 运行中唯一 Exit 与单人 / Duo Pause 的可交互外层均为 **44×44px**；漫画视觉面板可保持更紧凑，但必须放在 `aria-hidden` 内层，不得缩小按钮本体。Duo Pause 需为全局 focus ring 保留至少 5px 场地内边距。
- 赛前高频触控合同同为 **≥44×44px**：Header Profile、Home 分区入口、Showcase/Library filters、搜索/下拉、Track 返回/试听与全部 Run 配置、Sound check、Adjust timing、No sound/Settings、Fullscreen、Settings Key preset。头像与试听允许更小的 `aria-hidden` / 伪元素视觉面板，但按钮或链接本体不得缩小；底部导航、主 CTA 与键帽也纳入几何回归。
- **短横屏合同**：viewport 高度 ≤520px 时，44px 顶部 meta 保留 Exit、曲名和当前模式，单人 / Duo 场地占满其余动态视口，判定线、judgment 条与 Pause 不得出屏，document 不得滚动。宽度 ≤700px 时 Duo 仍左右分屏；ready card 按 Left/Right 给出键盘座位或触屏四 lane 提示，live meta 可隐藏重复提示，overlay 由自身承担纵向滚动。

### 5.4 页面键盘与读屏导航

- 每个使用 `Layout` 的页面在重复页头导航之前提供 `Skip to main content`，默认移出画布但保持为首个 Tab 停靠点；聚焦时进入 safe area，以高对比样式和 ≥44px 高度显示，Enter 聚焦唯一 `#main-content`。

## 7. 渲染与性能架构

- **精灵预渲染**：四道菱形音符启动时各渲染一张 120px 离屏 canvas（含黑描边、0.4 透明度高光三角），每帧仅 `drawImage`——代码注释明示 shadowBlur 是旧版掉帧主因，已彻底移除。
- **rAF 循环**：判定 `tick` + Canvas 绘制全在循环内，**零 React 重渲**；DOM HUD 用 20Hz 独立 rAF 只在值变化时写 text/style，`getResult()` 每帧分配对象的坑已被规避。
- **角色环境层**：当前街区 512w WebP 只加载一次并在背景 wash / rays 后、轨道与玩法对象前绘制；使用 screen 合成与圆角裁切，单人透明度随 SIGNAL 平滑升温，Duo 的四档上限为 0.06 / 0.09 / 0.12 / 0.16。Reduce Motion 直接切换目标透明度。角色不再作为 z-index 位于 Canvas 上方，因此 lane 4 的音符、判定线和 MISS / PERFECT 不可能被其遮住。
- **Chord 组关系**：同一 Chord 的最左/最右分道中心由黑色外框与米白内芯双描边连接，音符菱形最后覆盖连接轨；部分命中时只降低连接轨权重并保留到全组结算。每帧以一次无排序、无临时数组的常量级 lane 扫描计算边界和剩余比例。
- 判定反馈以 `JudgeFx.scoreGain` 携带引擎在该事件发生时已经提交的精确分数；直接输入和 `tick()` 一帧批量补判均不得从后续 Combo 状态反算浮字。这样 Chord assist Great 跨倍率门槛后，即使同批后续 Miss 已断连，Canvas 仍显示真实得分。
- **外轨判定边界**：`PERFECT / GREAT / GOOD / MISS` 的实际字体宽度、描边、当前弹出缩放及本帧震屏统一参与水平约束；只有即将越界的文字组向内收，星爆与得分仍在真实 lane。四种主词宽度按字体缓存，并在 Anton 加载完成时失效。
- **Combo 断裂层**：已有 Combo 归零后的 520ms 内，在场地水平中心和顶部 HUD / 判定线之间绘制 `COMBO BREAK`；触发源是状态机单调断连事件序号，而非帧末 Combo 数值，同帧后续 Good/Miss 之外的命中不能吞掉提示。该必要状态文案不位移，独立于 Fancy FX，并取消仍在播放的 Combo 里程碑。Reduce Motion 保留文字与原位淡出。
- **Combo 里程碑层**：用上一帧与当前帧 Combo 区间查找跨过的最高阈值，覆盖 Chord 在一次输入批次中递增多次的情况；若本帧发生断连则抑制里程碑，保持失败语义优先。新建 chart/session 与 Restart 均归零比较基线。
- **来音绘制优先级**：持续 Combo 数字保留原位置和视觉升温，但先于音符及 Chord 连接轨绘制；开局 `3 / 2 / 1 / GO` 同样先绘，保留 3 秒负时间预滚、96px Anton、位置、样式、音效和时序。任一上下文与中央来音包围盒在窄屏相交时，预滚音符与连接轨后绘覆盖上下文，战绩或倒计时不得挡住下一次输入目标。
- DPR ≤ 2；`ResizeObserver` 自适应；震动/粒子/里程碑闪光全部受 `fancyFx` 开关 + Settings `reduceMotion` + `prefers-reduced-motion` 三闸。Reduce motion 不删除关键结果：判定星芒、标签与 `+分数` 保持原位淡出；系统偏好在已开始的对局中改变也会即时生效（✓ 总纲 §4.8）。
- 打击感（fancyFx 开时）：Perfect 22 粒 / Great 14 / Good·Miss 8，方形碎片 + 重力；判定 150ms 震屏（Perfect 6px / Miss 7px）；连击里程碑 [10,25,50,100,150,200,300] 全屏 Anton 大字 + 强震。
- HUD 视觉语言（RESONANCE v2.0）：墨底 `#12100F` + 朱红呼吸 wash（随 BPM 余弦脉动）、斜切表现卡 + 纯黑描边；左上显示 Score、按**已判定音符**计算的 live Accuracy、`judged/total` 与进度条；倒计时与尚无任何判定时用 `ACC —` 表示未知，第一次判定后再转为两位小数百分比，不用虚假 `100.00%` 预先奖励。Duo 虽使用半宽/半高紧凑卡，仍保留可见 `ACC` 标签和独立 `judged/total`，不用无标题数字让新玩家猜测。普通完整 Arcade 若有本机纪录，赛前显示 PB 目标，开局后在 Score 卡以 20Hz 显示原始 `PB −924K / TIED / +1.2K` 分差；有效分享挑战改用优先级更高的 `GOAL`，Daily/Practice/Casual 不叠加不适用目标。该差值不是基于缺失的逐音符历史伪造 pace。Arcade 再在卡内显示 HP 标签、余量条和精确值（≤30 转红），Casual / Practice 不显示；顶部栏独占曲名/难度，SIGNAL 居中、暂停在右。≤520px 的单人竖屏把表现卡收为场宽最多 30%、高最多 72px，并压缩顶部安全区；320px 仍完整显示 `PB −924K`。First Shift `Find the line` 沿用同一左上锚点，最多放宽至 36% 保住短指令可读性。Fullscreen 文字继续收为具 44×44px 命中区的图标，曲目元数据、Score/目标、SIGNAL 与 Pause 不重叠。旧 Canvas HP 横条已删除，避免横穿卡片、SIGNAL 与暂停区；HP 归零时覆盖场地显示硬边红卡 `ARCADE RUN / SIGNAL LOST / HP DEPLETED`，立即冻结输入并在 300ms 后交付结果。连击和瞬时判定只保留判定线视线附近的一份 Canvas 反馈。四档累计判定不在四条轨道底部常驻，避免全局 Perfect / Great / Good / Miss 被误解为分轨标签，完整统计统一留到 Results。Practice 手动非 1× 时持续显示 `Practice tempo`；临时自动慢放改显示实时倍速与剩余秒数，结束后恢复所选 tempo。判定文案 Anton 斜体墨描 + EARLY/LATE 微偏移（≥8ms 时显示），连击四档增热（米白→琥珀→朱红）。
- 窄屏 Duo 例外：场宽随视口变窄时，每位玩家的 `SIGNAL` 徽标可稍向右偏离几何中心，但不得覆盖同场 Score / ACC / 进度，也不得碰到独立 Pause 命中区；667×375 横屏和 320×568 竖屏都须守住该边界。

## 9. 页面与路由

自研 router（`router.tsx`，History API + 模式匹配 + `Link/useSearchParams`），base 可配（本地 `/beatscape/`，CF 构建 `/`）。CF 根构建的新内部链接统一输出根路径，同时继续解析旧候选发出的 `/beatscape/*` 深链；命中旧链时 canonical / `og:url` 立即声明对应根路径，下一次导航也会收口到根路径。`Link` 仅拦截未修饰的鼠标主键点击；Ctrl / Cmd / Shift / Alt + 点击、中键、显式 `target` 与 `download` 保留浏览器原生行为。顶部导航与手机底栏的当前页链接输出 `aria-current="page"`；Calibration 作为 Settings 子流程，在 `/calibrate` 同样只把 Settings 标为当前位置；桌面 Track 详情则继续只把 Library 标为当前位置。手机 Track 仍隐藏全局 tabbar，使用当前曲目的专属固定操作栏。手机固定底栏的 Home / Library / Board / Settings 使用同一 24px 内联 SVG 语法，避免系统字符跨平台漂移；Board 为排名柱形。中心动作按真实意图选择图标：Review / Calibrate 使用目标图标，切换模式或档位使用 Play，精确重玩及 Daily / 挑战 / 故事 Retry 使用 Replay；文本及 `aria-label` 保留完整动作、曲目与局配置。

Library 来源合同由 `lib/libraryReturn.ts` 统一处理：只有本地、精确的 `/library`（可带 query）可作为 `returnTo`。Library 卡片把非默认发现状态传给 Track，Track 的 Library / Play / Duo 链接继续传递；Play/Duo 的赛前显式退出和加载失败出口保留返回链。单人 finish 后 Results 继续携带该来源，Replay、教练分支、Miss Practice、Daily retry、Change setup 与 Browse Library 全部复用；分享链接和 canonical 排除本地发现参数。直接进入这些路由时 URL 保持干净；外站、协议相对和 `/library-*` 路径降级到 `/library`，Library 入页时消费并清除 `returnTo`，避免嵌套。

Library 试听合同：每张当前已展示的卡提供具名 44px Preview / Pause；音频使用 `preload="none"`，用户点击前不发请求。共享 AudioBar 所有权保证新试听真正开始时暂停上一首，播放失败、暂停、结束、换源、卸载或切后台都会释放状态。试听条参与卡片自身高度计算，并完整避让移动固定导航。Home / Library 精选卡的人工片段在 metadata 未加载时也以已知 `segmentSec` 显示 0–15 秒时间轴；首次播放在 metadata 到达后跳到 `previewStart`，进度条、读数、键盘 Home/End 与自动停止都映射到片段而不是 48 秒源文件。

Track 详情试听合同：详情页使用独立 `preview_48s.m4a` 资产，但一次试听只暴露明确的 15 秒窗口；读数与 slider 从 metadata 到达前即为 0–15 秒，键盘 Home/End 和播放到点都停留在该相对时间轴。游戏切片时长、Library 普通卡片与完整流媒体版不受此窗口影响。

移动次级交互面积合同：在不放大可见字号、图标或试听轨道的前提下，顶部 Home Logo、Radio 季标题、Results `Miss review`、Local Board / Results 的 Profile 链均提供 ≥44px 实际目标；AudioBar 的 8px 可见 seek rail 通过上下透明 hit slop 提供 44px pointer 命中带。320×568 下不得因此新增横向溢出、挤掉 Home 首屏动作或覆盖固定 tabbar。

**LastRun schema（Results 唯一输入）**：`v, scoringVersion?, track_id, title, artist, tier, mode, score, accuracy, maxCombo, grade, fc, ap, failed?, counts{perfect,great,good,miss}, totalNotes, missEvents?, timing?, durationMs, endedAt, shiftStep?, prevBestScore?, surgeMaxTier?, seekedFrom?, seekedUntil?, practiceRepetitions?, practiceAttempts?{accuracy,misses,score,grade}[], challenge?{score,accuracy,grade}, dailyDateKey?`。缺对象或存档损坏 → Results 显示品牌化 `No result yet`，提供选曲与 Home 恢复动作，不向玩家暴露内部深链参数；`missEvents` 为旧存档兼容可选字段，Miss 总数始终取 `counts.miss`，有总数但无坐标时显示 details unavailable；损坏的可选 timing / challenge / Daily identity / Drill trend 会被单独丢弃，不连带杀死有效成绩。Daily identity 只允许合法 UTC date + Standard Arcade + 完整局；带 `seekedFrom` 的分段 Practice 在写入和读取两侧都丢弃 challenge / Daily。`practiceRepetitions` 只允许同时存在合法 `seekedFrom+seekedUntil` 时的 2–5 整数，否则读取与写入都移除；`practiceAttempts` 还必须与该轮数精确同长、每项字段有效，否则只移除趋势。存在趋势时标题统计仍只代表最后一轮，Results 另行比较每轮与首末变化。

**对局时长口径**：`durationMs` 仅统计实际进行中的时间，不计赛前等待、暂停层及退出确认。单人 / Duo 在暂停或退出请求发生时立即记录时钟边界，UI 可见与计时状态同步；音频恢复和 Keep playing 完成后才继续计时，不能把用户留在确认面板或系统暂停的时间计入 Profile 的 `Time in the Scape`。

**仍未实现**：`bs_player_id`。当前段位、成就与统计完全设备本地化，不依赖账号或游客 UUID。

**分享**：普通结果的 `Share this run` 紧随核心成绩/奖励后的唯一 `Next move`；当该建议为 Review 时，默认折叠的 Miss review 先紧贴教练卡，Share 再出现，避免玩家为执行建议跨过分享和剧情；其余建议仍由 Share 直接承接。Share 继续排在通用电台回信与底层诊断之前；≤640px 优先保证教练主 CTA 完整位于初始 viewport 固定底栏上方。First Shift 成功推进时保持故事下一首优先，分享排在完整连接结果之后；当前节点未推进时不提示分享，并隐藏与剧情 Retry 重复的页尾通用下一局区。完整局 Copy link / 文件分享文案指向 `"{origin}{base}/play/{track_id}?tier=…&mode=…&challenge=1&target=…&acc=…&grade=…"`；接收者赛前看到目标，结算比较最终 score 并显示 cleared / tied / missed 与分差。Results 精确复赛复用原目标；切换模式或 tier、返回 Track setup、进入分段 Practice 会离开挑战，因为规则不可比；完成后 Copy link 则用当前成绩建立新目标。目标只来自可修改 URL，是无账号好友挑战，不改变 PB / Local Board / Daily / 生涯；分段 Practice 在 URL、存档写入和存档读取三层均不保留目标。CF 正式构建分享与内部链接统一为根路径，新路由仍兼容旧 `/beatscape/*` 深链；从旧链打开时 canonical 与 `og:url` 也立即指向根路径。英文文案同时带 No account / no ads / browser-local。文件 Web Share 使用 1080×1350 竖版 PNG；桌面图片剪贴板保留 1200×630 横版；`Download 4:5` 在三种能力档均可用。竖版另含 BeatScape 品牌、挑战 CTA 与站点地址，文件名后缀 `-4x5.png`；不可用的 Share/Copy 不渲染。海报须在结果页预先生成，Share/Copy 点击处理器不得先等待字体或 Canvas PNG 导出，以保留短暂用户激活；曲库元数据未返回时先用成绩生成，元数据到达后可补全街区装饰，不阻断分享。准备中禁用图片分享按钮并显示状态，失败时保留重试及下载出口。

## 13. 构建与部署

```bash
pnpm dev:beatscape            # Vite 5175，base /beatscape/，根路径 302 → /beatscape/
pnpm --filter @musicsaas/beatscape test   # vitest run（node 环境）
npm run build                 # tsc --noEmit && vite build（base /beatscape/）
npm run build:cf              # VITE_BASE=/ → Cloudflare Pages 构建
npm run preview               # 从 dist 入口自动识别上述两种 base，直接预览实际产物
npm run deploy:cf             # build:cf + wrangler pages deploy dist --project-name=beatscape
```

- 依赖仅 `react / react-dom`（runtime 零额外依赖）；dev：vite/vitest/typescript/plugin-react。
- 候选预览读取 `dist/index.html` 的 hashed module 入口推导实际 base；本地构建打开 `/beatscape/`，Cloudflare 构建打开 `/`。Playwright 复用同一无隐藏环境变量的命令，避免人工预览与自动验收测试不同产物路径。
- SPA fallback 三套齐备：CF `public/_redirects`（`/* /index.html 200`）、`netlify.toml`（+ catalog 1d / assets 1y immutable 缓存头）、`vercel.json` rewrite。
- `index.html`：无外部字体依赖；Anton/Sora/IBM Plex Sans/Mono 的 12 个 Latin/Latin Extended WOFF2 由 `styles.css` 引用并打入 hashed `/assets/`；SVG data-URI favicon（共振菱形）。
- PWA：`manifest.webmanifest` 提供 standalone 安装、192/512 maskable 图标与 Play/Library shortcuts；`pwa.ts` 仅在 production 注册当前 base path 下的 `sw.js`，worker 文件强制 revalidate。
- PWA 升级：`release.mjs prepare` 根据候选包内容为 `sw.js` 写入 16 位 shell 版本，每个发布使用独立 `beatscape-shell-{version}`。升级 worker 不调用 `skipWaiting()`，会保持 waiting，直到仍由旧 worker 控制的页面关闭；旧页面因此继续读取配套的 hashed chunks，正在进行的单人/Duo 对局不会被中途换版本。新 worker 激活后才 claim 页面并清理旧 shell；音频、预览与 runtime 有界缓存跨发布保留。
- PWA 安装留存：主包在 React render 前捕获真实 `beforeinstallprompt` 并阻止浏览器立即打断首访，把一次性事件保留到玩家完成有效旅程；只有成功 Results 在核心续玩、分享与回信后渲染安装卡。原生 `prompt()` 只由 `Install app` 的当前用户手势调用一次；接受/拒绝/异常、外部 `appinstalled` 与 standalone 启动均清除入口。浏览器未提供该事件时不显示安装按钮；失败局和未推进 First Shift 不以安装推广抢占恢复动作。
- 加载拆分：`PlayField` 是独立 async chunk；Home 待机不请求它，Play+Sound 手势后与真实谱面并行获取。Play / Duo 直达页在自身 chart 加载期并行预取同一模块，避免 ready 前再闪一次加载态。当前同环境构建主 JS 从 424.96 kB / 136.98 kB gzip 降到 367.49 kB / 119.09 kB gzip（约 −13.5%），对局 chunk 为 62.19 kB / 20.18 kB gzip。
- First Shift 已选曲音频：剧情页确认下一曲后延迟 500ms 才预取其版本化完整音频；点击该页的普通 Play 链接时将进行中或已完成的同一下载交给对局解码缓存，不额外创建 AudioContext 或第二个请求。未开局便离页会取消；浏览器启用 `Save-Data` 时不自动预取；未接管的下载最多保留 60 秒，失败后正式开局仍走原有加载/重试路径。Home 主 CTA 直接进入 Play，不经过此剧情预取。该优化只改变剧情阅读时间内的传输时机，不改变音频内容、解码、谱面或 WebAudio 判定时钟。
- 全局路由恢复：普通 lazy route 在桌面 pointer enter、键盘/手柄 focus 或触屏 pointer down 时按真实导航意图提前取包；进行中/已成功请求复用，预取失败会释放并允许正式导航重试，Home/Library/Play/Results 等 eager route 不额外发请求。直达文档在 head 用 pathname-aware bootstrap 只预取当前 Track、Duo、Characters、Radio、First Shift、Calibration、Settings、Local Board、Profile、Legal 或 NotFound chunk，并兼容旧 `/beatscape/*`；105 个静态 Track 分享/发现页改用更小的声明式唯一 preload。发布器在任一映射 chunk 缺失或歧义时失败，React 接管复用同一模块请求。Suspense 边界只替换 `Layout` 内的主内容；品牌页头、当前 `aria-current` 导航和手机固定 tabbar 在分包等待期间保持稳定，快速 loading 预留剩余视口，避免 footer 上跳。等待超过 3 秒后请求继续进行，但主内容升级为带 The Late Static 品牌锚点的 `Still connecting`，同时提供保留当前 URL 的整页 Reload 和指向 `BASE_URL` 的原生 Home 出口。Router 外的 `ErrorBoundary` 继续捕获 rejected lazy import / render 崩溃，以 `Signal lost` 隐藏原始模块异常并用整页重载重新创建已拒绝的 Promise。所有动作 ≥44px，320px 不横向溢出。
- 静态单曲发现：`release.mjs prepare` 按当前 catalog 生成 `track/{id}/index.html`、105 条 sitemap URL 与 420 条精确 CF rewrite（根路径 / 旧 `/beatscape` × 有无尾斜杠）。每页在 JavaScript 运行前提供独立 Title / Description / canonical / OG / X 与 `MusicRecording` JSON-LD，并引用自身带内容哈希的 1200×630 分享卡；卡内使用已归档 OFL Anton / IBM Plex Sans 烘焙曲名、艺人、BPM、曲风、街区及浏览器游玩 CTA。发布器要求 105/105 图片存在且尺寸正确，不再回退通用站点卡。未知 ID 仍走 SPA fallback。Track 卡保留空 early-audio slot，不复制只服务 `/play` / `/duo` 的全 catalog 音频映射。
- 离线边界：首装预缓存当前发布的 app shell、catalog、初始入口 JS、hashed CSS/字体等非 JS 资产与 128px 角色图；lazy route / gameplay JS 在实际请求后写入同一版本化 shell cache。完整音频在实际打开后按需缓存最多 6 首，预览最多 12 首，JSON/封面等 runtime cache 最多 500 项。字体和 hashed assets 为同源 immutable 内容，cache match 忽略 `Vary: Origin`；支持离线导航、生产字体和已缓存音频 Range 206。`Offline mode` 在已缓存曲目的赛前仍可见，单人/Duo 真正运行后抑制横幅，避免 online/offline 事件改变场地几何，离开运行态自动恢复；未打开的新曲仍要求联网，不预下载整套 491.7 MiB 曲库。
- **部署状态**：线上 CF Pages 仍为 35 首旧版——85 首版本已构建待重部署（SESSION P0）。
